# 競輪AI予想 毎朝自動更新

毎朝、日本時間6:30ごろに自動で当日開催の全レースを取得し、AIモデル（keirin_predictor_v2.htmlと同じロジック）で計算した予想を1枚のWebページにまとめます。スマホのブラウザでブックマークしておけば、開くだけで見られます。

## セットアップ手順（最初の1回だけ）

### 1. GitHubに新しいリポジトリを作る
- GitHub にログイン → 右上の「+」→「New repository」
- Repository name: 好きな名前（例: `keirin-ai-daily`）
- Public のままでOK（Privateだと後述のGitHub Pagesが有料プラン限定になります）
- 「Create repository」をクリック

### 2. このフォルダの中身をリポジトリにアップロードする
このチャットから受け取ったzipを展開すると、以下の構成になっています。

```
keirin_auto/
├── .github/workflows/daily.yml   ← 毎朝の自動実行スケジュール
├── docs/index.html                ← 生成される予想ページ（最初は仮の内容）
├── scripts/
│   ├── model.py                   ← AIモデル本体
│   ├── scraper.py                 ← 出走表を取得するスクレイパー
│   ├── report.py                  ← HTMLレポート生成
│   ├── run_daily.py               ← 上記3つをまとめて実行するメインスクリプト
│   └── requirements.txt
└── README.md（このファイル）
```

GitHubのリポジトリページで「Add file」→「Upload files」から、このフォルダの中身（`.github` フォルダも含めて）をまるごとドラッグ&ドロップしてアップロードしてください。フォルダごとドロップすれば階層構造も保たれます。

### 3. GitHub Pages を有効にする
- リポジトリの「Settings」タブ →左メニューの「Pages」
- 「Build and deployment」の「Source」を **Deploy from a branch** に設定
- Branch を **main**、フォルダを **/docs** に設定して「Save」

数分待つと、`https://（あなたのユーザー名）.github.io/（リポジトリ名）/` というURLでページが公開されます。このURLをスマホのSafari/Chromeでブックマークしておけば、次回からタップするだけで開けます。

### 4. 動作確認（手動実行）
- リポジトリの「Actions」タブ →「競輪AI予想 毎朝自動更新」を選択
- 右側の「Run workflow」ボタン→もう一度「Run workflow」で手動実行
- 1〜2分で完了し、`docs/index.html` が自動更新されます（Actionsの実行ログでエラーが出ていないか確認してください）
- 公開URLをリロードして、その日のレース予想が表示されるか確認してください

以降は、毎朝日本時間6:30ごろに自動実行され、`docs/index.html` が自動でコミット・公開されます。

## 締切通知（スマホへのプッシュ通知）

締切10分前ごろに、スマホへプッシュ通知を送ることもできます。

### セットアップ手順
1. スマホに **ntfy** アプリをインストール（iOS App Store / Google Play、無料・アカウント登録不要）
2. `.github/workflows/notify.yml` を開き、`NTFY_TOPIC` の値を他人に推測されにくいランダムな文字列に変更する
   （例: `keirin-alert-8f3ac2b1` のような、あなただけが知っている文字列。ntfy.shはトピック名さえ知っていれば誰でも購読・送信できる公開サービスのため、簡単な名前は避けてください）
3. 同じファイルの `PAGES_BASE_URL` を、あなたのGitHub PagesのURLに変更する（例: `https://あなたのユーザー名.github.io/リポジトリ名`）
4. ntfyアプリを開き、「+」ボタンから、手順2で決めたトピック名と**全く同じ文字列**を購読（Subscribe）する
5. GitHubのActionsタブから「締切通知チェック（5分おき）」を選び、一度手動実行して届くか確認する

### 仕組み・注意点
- 毎朝の本体ワークフローが生成する `docs/_deadlines.json`（軽量な締切一覧）を、5分おきの別ワークフローが読みに行き、締切の8〜13分前のレースがあれば通知を送ります（サイトへの再スクレイピングは行いません）
- 同じレースに二重に通知しないよう、送信済み記録を `docs/_notified.json` に保存しています
- GitHub Actionsの5分おきスケジュールは、混雑状況によって数分ずれることがあります（正確に10分前ぴったりではない場合があります）
- ntfy.shは無料の公開サービスのため、通知の内容は「絶対に他人に知られたくない」というレベルの機密ではないことを前提にお使いください

## 予想成績の評価（仕様・データの流れ）

```
scraper（出走表・並び予想）→ model.predict_race（確率）→ prediction_log.record_predictions（締切前に1回だけ記録）
  → 締切後 prediction_log.update_results（日の結果ページ→着順）→ docs/_prediction_log.json
  → calibration.update_params（毎日1回・有意性ゲートつきの自動補正）→ docs/_model_params.json
  → evaluation.build_report（確率の質・前向き検証）→ docs/_eval_report.json
  → report.render_results_page → docs/results.html
```

**成績の分母（評価対象）**: 結果が3着ぶん確定していて、かつ「締切より前に予想を記録した」レースだけ。
除外は、結果待ち／着順不足（中止・欠場・解析失敗）／締切後に初めて記録したレース（`late`）。
締切後の記録は、そのレース自身の結果が当地成績・対戦履歴・直近の調子の集計に取り込まれたあとに予想を
計算している可能性があり、未来情報が混ざりうるため、成績にも補正の学習にも使いません。
`rec_at`（予想の記録時刻、JST）がない旧ログは除外せず、ページ上で件数を別に表示します。

**指標の定義**（予想成績ページと同じ）: 本命＝予測1着率が最大の選手。1着率／連対率／3着内率＝本命がその着順以内に入った割合。
3連複BOX＝予測上位3車が実際の3着内の3車と一致（1点買い）。3連単上位1点／5点＝記録した3連単の上位1／5組合せのどれかが的中。
Log Loss／Brier＝1着確率の質（`evaluation.py`）。校正表の信頼区間は Wilson 95%。

**自動補正の採用条件**: 尤度比検定（1着率の絞り込み・方程式バフは3.84、2着・3着の補正は5.99）を超えたときだけ適用。
超えなければ基準値のまま。学習に使うのは締切前記録のレースだけで、方程式バフ導入後はバフ前の確率(`p0`)で学習する。
最低件数: 1着率120件・方程式バフ80件・2着3着は車立てグループごとに100件。直近60日。
ロールバック: `docs/_model_params.json` を削除（または `active` を false に）すれば基準値に戻ります。

**前向き検証**（`evaluation.walk_forward`）: 評価日ごとに、それより前の日だけで補正器を学習し、その日を評価。
現行AI・γ再学習・γ＋方程式バフ・等調回帰（候補）を同じレースで比較し、損失差の95%区間（日単位ブートストラップ）が0を
またぐ間は「改善とは言えない」として採用しません。等調回帰は本番には組み込んでいません（評価のみ）。

**回収率・収支**: 払戻・オッズをログに保存していないため**評価不能**です（架空の値は出しません）。

**既知の限界**: 同着は着順の数字だけでは判別できない。欠場・失格は結果ページの形式が確認できていないため、
「着順不足」以外では区別していない。開催（同じ日・同じ場）の相関はウォークフォワードの日単位ブートストラップでのみ考慮。

## 注意点（正直にお伝えします）

- **スクレイピング先サイトの構造変更に弱い**：keirin.kdreams.jp のページ構造が変わると、取得できるレース数が0件になったり、一部データが欠けたりする可能性があります。その場合はActionsのログにワーニングが出るので、時々確認してください。
- **並び予想（ライン）は当日の公開タイミング次第**：サイト側が並び予想を公開する前の時間帯に実行されると、ライン補正なしの予想になります。
- **的中を保証するものではありません**：あくまで過去データに基づく統計的な参考情報です。
- 実行時間を変えたい場合は `.github/workflows/daily.yml` の `cron: "30 21 * * *"` の部分を編集してください（UTC指定なので、日本時間から9時間引いた時刻を指定します）。

## うまくいかない場合

- Actionsのログを見て、どのステップでエラーが出ているか教えてください
- 「レースが0件」の場合は、`scraper.py` の抽出パターンをサイトの実際の構造に合わせて調整する必要があります

## 2026-10 モデル再構築（段階別の追加補正）
- 結果の読み取り: 着順が壊れて見えるレース（着順数より1つ大きい車番が先頭に来る形）を検出し、学習・評価から除外して結果を取り直す（`scripts/validity.py`）。パーサも見出し行の誤読を避けるよう修正。※実ページHTMLでの確認は未了。
- `scripts/stage_cal.py`: 1着の決まり手補正（逃が基準の exp(θ)）と、2着・3着の同ライン補正を毎日学習。件数・開催場数・尤度比(p<0.01)・日単位1日抜き交差検証のゲートを通ったときだけ適用。初回適用は基準値との平均で縮める。8車以上は150レース・4開催場がそろうまで適用しない。
- 補正が有効なグループでは、日々のγ補正・ライン追走補正は使わず既定値に戻す（二重補正の防止）。
- 方程式バフは廃止（方程式は参考表示のみ）。
- 1着補正に「本命級(30%超)の過信を直す折れ線(hinge)」と「ライン3番手以降」の項を追加。買い目一覧に損益分岐オッズ（=100÷確率%）を表示。
